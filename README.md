# Задание 1 Разделить проект Mesto на несколько микрофронтендов
## Уровень 1. Проектирование. Выбор фреймворка для создания микрофронтендов.
Приложение реализовано на React. Точка входа в приложение файл index.js. Структура главной страницы определена в App.js, в нем описаны обработчики для компонентов. Взаимодействие с бэком -- в api.js и auth.js, каждый со своим общим url. Небольшое приложение, но с сильными зависимостями, что ограничивает возможность масштабирования и независимой параллельной разработки несколькими команданми.

Независимость разработкии несколькими командами, сокращение T2M фичей и гибкая масштабируемость -- основные вводные для принятия решения по выбору фреймворка.

В качестве фреймворка выберу Webpack Module Federation, который позволит обеспечить независимость разработки и развертывания микрофронтенда, даст возможнсоть использовать разные версии библиотек без конфликтов и позволит оптимизировать использование ресурсов за счет ленивой загрузки модулей. В качестве фреймворка для всех микрофронтов предлагается оставить React, т.к. текущая реализация написана на нем, а также нет специфических требований или каких-то ограничений в компетенциях команд для того, чтобы рассматривать другие фреймворки. Испольование везде React -- дополнительный аргумент для выбора Webpack Module Federation. Для обеспечения независимости частых обновлений микрофронтендов и гибкого масштабирования будет выбран run-time метод инетграции с клиентской композицией для создания богатого интерактивного пользовательского опыта. Для обеспечения слабой связанности между компонентами, упрощения масштабируемости и легкого отслеживания изменения состояния через события будет применен паттерн Pub/Sub для коммуникации между фронтендами.

## Уровень 2. Планирование изменений. Определение, какие компоненты в какой микрофронтенд пойдут
Чтобы в будущем проект могли развивать несколько независимых команд, декомпозируем фронтенд проекта по бизнес-функциям, плюс хост-приложение:
- Управление фотографиями и лайками к ним
- Управление профилем пользователя
- Хост-приложение

Новая структура проекта будет выглядеть следующим образом:
  /mesto
    /cards-microfrontend
      Api.js                 // Взаимодействие с бэком
      Card.js                // Компонент удаления карточки фото, добавления и снятия лайков
      AddPlacePopup.js       // Загрузка фото
      PopupWithForm.js       // Компонент для всплывающих окон
    /profiles-microfrontend
      Api.js                 // Взаимодействие с бэком
      Auth.js                // Взаимодействие с бэком в части аутентификации
      EditProfilePopup.js    // Компонент редактирования данных профиля
      EditAvatarPopup.js     // Компонент редактирования фото профиля
      Login.js               // Компонент управления входом
      Register.js            // Компонент для регистрации
      InfoTooltip.js         // Компонент для нотификаций об успешных/неудачных операциях по регистрации
      PopupWithForm.js       // Компонент для всплывающих окон
    /host-microfrontend      // Динамическая загрузка удаленных модулей
